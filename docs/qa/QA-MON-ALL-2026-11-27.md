## Set-up

- PostgreSQL 18.7 ran in a task-owned container at 127.0.0.1:55433, database `kpone_qa_mon`. The host, port and database name were checked before the first HTTP request.
- The env file was kept outside the repo. No real `.env` was used. kpjaya.com and real databases were never touched.
- PHP 8.4 ran in the `serversideup/php:8.4-cli` container. The frontend was built with `npm run build`.
- Data: `migrate:fresh`, then `KPOneReferenceSeeder` and `KPOnePresentationSeeder`, then `kpone:director-branches`. All six TRIAL-DATA phases were then run through their phase classes (the same services the `kpone:trial-data` command uses), and every phase completed. The trial data has no accounts for `branch_manager`, `account_assistant`, `store_admin`, `medical_assistant` or `locum`, so `qa.*@kpjaya.test` accounts were added for them through `StaffProvisioningService`.
- Method:
  1. A sweep for every role: sign in, open the home page, then open every link in the shell and account menus in Chromium. Each page was checked for HTTP status, page errors, console errors and blank content. The same session also requested 173 GET routes without parameters, to build the access matrix.
  2. Testers drove the main tasks end to end through the real UI: the clinic flow, Panel and finance, stock, HR, admin and the TV.
- Roles: 17 exist on `main`. **`account_executive` does not exist on `main`.**
- Tests ran on 27 Nov, from about 22:50 to about 00:10 MYT (just past Kuala Lumpur midnight).

## Failures

Each item below gives the role, the page or URL, the action, what happened, the suspected file and the screenshot.

### Security (reported first)

1. **[SECURITY: scope, needs an owner ruling]**
   - Role and pages: branch_manager, on `/insights/sales?branch=CHERAS`, `/insights/today` and `/insights/payments`.
   - What happens: a Branch Manager at Puchong can pick another branch, or "All branches", in the Insights filter and see the totals for Cheras or for the whole organisation. The data is totals only, never patient-level.
   - Why it matters: the owner's 21 Nov decision gives the Branch Manager own-branch reports, and the CSV export already refuses other branches (`BranchOnlyExportScope`). But `insights.view.organisation` has been granted to every role since October.
   - Suspected file: `ClinicInsightsController` (no branch-only scope when viewing).
   - Shot: `branch_manager__insights_sales_cheras.png`.

No other security issue was found. Every role was checked against 173 routes, and the testers also probed specific URLs:
- The locum gets 403 on all 15 clinical, billing and stock pages it was tested on.
- The TV gets 403 on every patient, queue and Insights page. It can open `/staff` and `/dashboard`, which show only the TV account itself.
- Administrator, technical_admin, business_development and marketing get 403 on 20 patient, visit, consultation, billing, dispensary, Panel and report URLs.
- The medical_assistant gets 403 on the consultation encounter.
- The account_assistant cannot approve anything; a direct POST to accept returns 403.

### Blockers

2. **[BLOCKER] ca: Dispensary "Save all lines" loops after a quantity edit (code; on `main` and in #1274)**
   - URL and action: `/dispensary/{case}`. Change a saved line's quantity to a whole number (for example `12`), then press **Save all lines**.
   - What happens: the same line is PUT again and again (6 PUTs and 6 `dispensary.item_edited` audit rows in 4 s) until the page says "This Dispensary record changed. Reload and review the latest state."
   - Single **Save line** saves, but leaves the card dirty. Print label and Complete stay hidden until the page is reloaded.
   - Cause: `isDirty` compares the form value `"12"` with the saved `"12.000"` as strings, so `saveAll` keeps picking the same line.
   - Suspected file: `resources/js/pages/Dispensary/Show.vue` (`isDirty` around line 271, `formFor` around line 234, `saveAll` around line 822).
   - Reproduced on #1274; the code is identical on `main`.
   - **Update:** fixed on #1274 at head `6c3691f9`. The re-test passed (1 PUT per line, the card closes, and Print label and Complete come back). `main` keeps the bug until #1274 merges.
   - Shots: `ca__a3_saveall.png`, `ca__a4_qty11_saved.png`.

3. **[BLOCKER] ca: drug labels refuse to print (data and setup)**
   - URL and action: `/dispensary/{case}/labels`, then Print.
   - What happens: "Printing blocked — Address: 99 characters; label limit 96 / Address: 3 rows; label limit 2 rows".
   - Cause: `branch_business_profiles.label_address` is empty, so the label falls back to the full branch address.
   - Fix (setup, not code): before Monday, set a short **Label address** (96 characters or fewer, one line) in Business details for every branch, and check the real address on the Monday server.
   - Shot: `ca__drug_label_print_blocked.png`.

4. **[BLOCKER] ca: payments are paused while a cash count waits (process; works as designed in BIL-32)**
   - URL: `/visits/{visit}/billing`.
   - What happens: once a day's cash is counted, the CA gets no Finalize and no Add payment until the count is approved or returned. The Panel and pay-later buttons are in the same hidden Add menu. A count can be **approved only after midnight, branch time** (`CashClosingService.php:220`). So a count made during the day freezes payments for the rest of that day unless someone returns it for a recount.
   - The banner reads "waiting for the Branch Manager's approval" (`BranchDayGate.php`). The trial data has no Branch Manager account; the approve permission is also held by ca_supervisor, director and finance_officer.
   - The trial data leaves today's counts pending at CHERAS (`cash_closings` id 4) and SUNGAI_BESI (id 6).
   - Before Monday: approve or return every pending count, and tell the CA team not to count cash until the clinic closes.
   - Shot: `ca_cheras__payment_paused_pending_cash_count.png`.

5. **[BLOCKER] all staff: clock in and clock out are refused when PHP has no `gd` (environment)**
   - URL and action: `/spaces/me`, then POST `/hr/attendance/clock-in` or `/hr/attendance/clock-out`.
   - What happens: the compulsory photo returns 422 "Photos cannot be taken on this server. Ask HR to add your time as a correction."
   - Cause: the QA PHP image has no `gd`, and `composer.json` does not declare `ext-gd`, so nothing warns at install.
   - Suspected file: `app/Domain/HR/Attendance/Photos/ClockPhotoFiles.php:52`.
   - Action: run `php -m | grep gd` on the Monday server. Adding `ext-gd` to `composer.json` would be a separate slice.
   - Shot: `ca1__clock_photo.png`.
