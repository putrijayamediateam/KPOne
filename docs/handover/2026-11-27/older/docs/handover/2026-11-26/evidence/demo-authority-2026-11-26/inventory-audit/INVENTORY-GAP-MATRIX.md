No Post receipt / Dispatch / Approve / Record action was submitted. Local wrapper reports **not saving**: `window.claude.use('db')` is absent; do not claim persistence/ledger verification. This audit reads live main/CA source; it does not claim a fresh current-main application screenshot matrix. Prior application screenshots `/workspace/inventory-review/visual/` remain carried evidence only.

Runtime facts materially different from a palette-only reading:

- `Receiving`, `Transfers`, `StockCount`, `WriteOff`, `BatchHolds` resolve to `Stock` with selected tabs; `StockMovement`, `StockValue`, `MedicineSales` resolve to `Reports`. See wrapper lines252–257, not the older standalone layouts.
- `Stock` has group pills, secondary tabs/counts, selection-linked summary cards, search/filter toolbar, expandable rows, contextual actions and a collapsible helpful-info side rail. `My branch` / `HQ` changes the workspace. The current app instead has three primary stock tabs, grouped task links and a large Operations panel, with most workflows on separate pages.
- `InvReceive`, `InvDispatch`, `InvReceiveTransfer`, `InvReportDiff`, `InvPoApprove`, `InvRfq` open focused overlays above contextual Stock content. They are not simply links to arbitrary new full pages.
- Wrapper `NOTES` line244 explicitly excludes `InvLanes`, `InvMyWork`, `InvTimeline`, `InventoryFlow` as design notes. Do not turn them into production routes just because those HTML assets exist.
- Report controls have separate view/export permissions (wrapper220–227). A single Reports shell must not preload money/patient/branch data for tabs the actor cannot access.
- The wrapper and mock text are not the permission catalogue or accounting authority. Its samples still say cost policy unconfirmed and sometimes Director-only, show fixed names/locations/counts, permit simplified transitions and include proposed RFQ/Thursday/paid markers. Preserve newer owner-approved rules and real service capabilities.

## Proposed bounded sequence and acceptance gates

1. **Inventory shell + On hand vertical slice (P):** shared workspace navigation/group/subtab/header/filter/info-rail components, actual directory pagination and read-only row detail; context actions reuse existing forms. Add a precise data-contract proposal for nearest eligible expiry and by-form counts where not currently returned. Main source assertions pin old tab/link structure; enumerate a complete exact approval batch before changing them.
2. **Transfers + receipt/difference sheets (P):** real request→dispatch→receipt→independent difference-resolution path. Keep original routes/state and retry keys, verify successful and refused flows on synthetic data. Do not bundle STK61.
3. **Counts / write-offs / holds (P):** worklist+selected-detail layout with blind entry, stale-version refusal, independent reviewer, no unauthorized controls. Preserve STK45 reporter protections.
4. **Receiving / purchasing / supplier workflows (P):** contextual list+sheet modernization over existing endpoints. Keep STK47/48/49/61 domain work separate and explicitly staged when their approved source/schema is ready.
5. **Inventory reports (P):** coordinate shared Reports shell, then stock movement and valuation/margin/loss/medicine-sales exact projections. Preserve cost/staff/privacy scope and STK46 accepted-history semantics.
6. **HQ/RFQ/short dispatch gaps (D/Q):** recover/integrate approved feature slices first; ask only concrete new schema/assertion/behavior questions, not already settled owner choices.
