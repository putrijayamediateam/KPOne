## Change

The output-plan detail now shows a table with **Name, Kind and Alias**. The opaque item key remains visible as small secondary text under the name. English names come from the **bound release's frozen manifest**, through the same `WebsiteOutputPlanFields::targets()` projection used by the prepare form. There is no live-draft fallback. An unknown key shows **Unknown item** and retains its key, kind and alias.

`WebsiteOutputPlanFields::aliasRows()` is a pure display projection. `WebsiteOutputPlanService::page()` adds the derived rows after verifying/loading the bound release; it makes no additional database query. Vue renders these escaped rows instead of the generic aliases block; all other frozen content remains displayed through the existing structured-value component. The names are not inserted into stored plan JSON, evidence or hashes.

No migration, permission, dependency, state transition, audit change, public route, renderer, artifact or deployment. Existing W1e-1 and W1e-2-0 tables, guards and hashes are untouched. The existing authority, private/no-store/noindex and branch-switch clearing remain in place.
