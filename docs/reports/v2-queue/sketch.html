Consultation queue, Version 2 sketch (Yasmin, Queue & TV)

Static sketch only. Same page shell, tokens (cobalt primary, pink only for the logo dot and accents), hairlines and 14 px cards as Registration V2. Synthetic data. 1440 px table first, then the 390 px card list. Light and dark follow the system setting.

Question 1, Call next: toolbar button or a card above the table? Pick: toolbar button, the one filled cobalt button, at the right end of the toolbar (a full-width 44 px button at the top of the toolbar group on a phone). Reason: it is a frequent action that must sit in the same spot while rows reorder under it, a card above the table pushes the board down by 80 px on every refresh and competes with the room strip. The confirm dialog already names the patient (A-number, name, Urgent or Carry-over label), so the board does not need a "next up" card. The reason it is disabled (no room chosen, doctor busy, nobody ready) shows as one muted line under the toolbar and as the button's accessible description, and the button stays focusable. For Director and CA Supervisor the existing Doctor select is the target, so Apply then Call next works without a second picker.

Question 2, My room today: quiet strip or toolbar chip? Pick: quiet strip, one hairline card between the tabs and the toolbar, doctors only. Reason: it carries a select, a hint ("The TV shows this room...") and a warning state ("Call In stays blocked until you choose a room") that need words, which a chip cannot hold at 390 px. It turns warning-tinted only while no room is chosen, so on a normal day it is a single quiet line. A chip would hide the very state that blocks Call In.

Number cells never wrap (nowrap, tabular figures). Targets are 44 px below 1024 px, 36 px above. Wait ring: grey under 30 min, amber from 30, red from 60, with words "long wait" and "very long wait" so colour is never the only signal.
