## Scope and files

Freeze saved private website drafts into immutable canonical JSON evidence, review structured escaped content, retained media, omissions and a change list inside KPOne, and let a freshly authorised Director approve, refuse or withdraw. Approval binds exact manifest bytes, not future draft changes, and is not verification of consent, rights, medical wording or display approval. No static website, HTML file/output generator, renderer, deployment, outbound call, public route/read API, external preview URL, URL mapping/redirect feature, job, queue, scheduler entry, dependency, settings/legal editor, intake, analytics, import or old-website use.

## Selection and consistent capture

Nine existing types: branch public profile, doctor profile, career posting, category, service, promotion, activity, FAQ and Little Shield. Every active branch needs a complete saved EN and BM profile; absent/incomplete profiles block. Other items are selected only through both saved inclusion flags; careers use their existing `open` intent (not a newly added flag). Both false means omission; one true and one false means a blocking language error. Archived/inactive branch items are omitted with a reason. Dates/open/inclusion do not schedule anything.

Reuses existing per-type completeness functions. It independently checks shared branches/parents/FAQ links in both languages, active same-organisation branches, valid included parents and service dependencies, category hierarchy, doctor consent, and manual registration/price/offer display references. All blocking errors name the release-local item key, language and field/dependency. No unsaved request content is read into a release. The error list is returned to the private prepare screen; failed attempts create neither release nor number and do not store submitted draft content.

Capture owns a repeatable-read DB::transaction, sets isolation before the first query, and uses the existing authority/organisation lock plus item, revision, branch, media and counter row locks. It refuses being nested in another transaction. The real concurrent-edit test starts an editor while capture is reading: the frozen languages remain from one snapshot, and the later edit appears only in the saved draft. Two simultaneous first prepares get unique sequential numbers. A narrowly bounded fresh-transaction retry handles only the named first-counter unique race; other errors propagate. No bypass flag, independent financial SQL, source rewrite or network operation.

## Tables, migrations and storage

| Migration | Adds / protects |
|---|---|
| 2026_10_26_000100_create_website_release_evidence.php | Seven tables below, restrictive provenance FKs, immutable evidence and versioned state/counter guards; down retains evidence |
| 2026_10_26_000200_grant_website_release_permissions.php | Exactly two firstOrCreate permissions, only missing grants, cache refresh; down never revokes |

- website_releases: immutable org/number/schema/hash/canonical manifest, omissions, creator and UTC time.
- website_release_items: exact source item/revision ids, revision hash, type/language/local key, public projection and content hash.
- website_release_media: source asset id, hash filename, MIME/byte count/dimensions/alt texts and encrypted retained sanitised bytes.
- website_release_actions: append-only prepared/approved/refused/withdrawn, actor, UTC time, exact hash and optional bounded private reason.
- website_release_controls: independent lock_version and current state.
- website_release_counters: independent locked organisation/year sequence; WEB/{local year}/{6 digits}; no reuse/backfill/decrease/delete/truncate, no clinical counter involved.
- website_release_commands: append-only actor/org/UUID/operation/keyed payload hash/result for replay safety.

PostgreSQL refuses UPDATE/DELETE/TRUNCATE of release/items/media/actions/commands. Controls permit only version+1 prepared→approved/refused or approved→withdrawn, and cannot be deleted/truncated. Retained bytes are private encrypted **PostgreSQL storage addressed by release and hash filename**, not writable public files. Media reads decrypt, verify SHA-256 and byte count and use the stored MIME. Initial capture additionally verifies source hashes, decoding, MIME, dimensions, rights, both alt texts and identifiable-person consent. Missing/retired/foreign/corrupt/mismatched media refuses capture. Original asset retirement or draft changes cannot replace historical bytes. No file export or public asset URL exists.

Source provenance FKs are retained, including website_release_items.source_revision_id → website_content_revisions. Existing update/delete/truncate protections are not weakened. No purge/delete job. Encryption-key backup/restore remains a deployment responsibility, not a feature in this slice.

## Permissions and actions

| Permission | Exact default holders | Access |
|---|---|---|
| website.releases.prepare.organisation | Director, Marketing, Administrator | Private list/detail/media and prepare |
| website.releases.approve.organisation | Director only | Approve, refuse, withdraw; also needs prepare authority |

HR Manager, Technical Admin, Finance Officer, Panel Officer, CA/CA Supervisor, Doctor and every other role gain no release access. Existing website draft view is insufficient. Director-only provisioning, canAssignRoles, canManage and protected authority boundaries remain unchanged. Catalogue and replay-safe migration agree.

Every mutation rechecks fresh permissions, organisation and effective branch, then uses a transaction, consistent locks, independent lock_version, UUID retry key and payload-conflict refusal. Approval requires exact typed release number, prepared state, version and unchanged canonical hash. Refuse/withdraw require bounded plain text up to 300; hidden/control/markup content is refused. A void-like closed state cannot reopen: prepare a new independent release. Matching retries return their original result; new-key repeated/invalid transitions refuse.

Values-free audit is exactly release_id, number, action, manifest_hash_prefix and item/media counts. It never contains content, private references, source values or decision reason. Reasons remain only in the private action history. An audit failure rolls back controls, evidence, commands and numbering; no action is released as successful. Reads require fresh prepare authority and org/branch checks, no-store/no-referrer/noindex. No new public API.
