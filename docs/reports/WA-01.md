## Scope

One reusable, icon-only inline WhatsApp SVG (green circular badge, white handset/speech bubble), `aria-label="Open WhatsApp chat"`, visible disclosure tooltip/title and a 48px default minimum target (44px in the follow-up 2 board rows). Real Chrome measured 47.998 CSS px in each dimension at the existing 80% zoom, exceeding 44px. New-tab anchors use `noopener noreferrer` and `referrerpolicy="no-referrer"`.

The component receives only `canWhatsapp`, a public route key and an allowlisted context. It never receives, normalises or builds a URL from a phone. The JS normaliser is retained solely as the PHP twin's independently tested shared contract.

Exactly one GET route, `patients.whatsapp`: `/patient-contact/{context}/{key}/whatsapp`. Context is `patient`, `claim` or, for the newly authorised board rows, `visit`. The server re-reads the patient's current saved phone and returns exactly `https://wa.me/<digits>` as a 302, with no message or query string. No KPOne outbound request occurs. Neither client-supplied phone nor message parameters influence the destination.

Owner clarification permits existing authorised phone props for patient details/edit and QR review to remain. No raw phone is added to a list payload or the button. List projections reuse already-read contact data only to add the eligibility boolean; the existing patient number/claim public id supplies the key. Existing masked values remain masked. This preserves current correction forms rather than redesigning them.

## Permissions and backend checks

No new permission, grant or migration. General Patient contact uses `patients.view.organisation` (Director, Resident Doctor, CA, CA Supervisor in the current catalogue). Search remains under its existing search permission. Claim context additionally requires both existing Panel permissions; its current holder is Panel Officer. Panel Officer cannot use the general Patient route. Finance Officer, Administrator, Technical Admin, Marketing, HR, BD, TV and every other catalogue role without the applicable contact permission get no action or redirect.

Inside `DB::transaction`, the domain service refreshes the actor, checks active actor and organisation, resolves the effective branch, and uses `TransactionalActorAuthority` to lock/reload actor grants, profile and current branch assignments. It additionally checks the freshly loaded grant set rather than relying solely on a cached role-permission map; direct permission-row revocation is tested while actor relations are already loaded. Patient lookups select only ids and the saved phone; claim lookups select only the patient id, and malformed claim UUIDs return 404 before querying. Claim context queries both organisation and branch; Patient context uses the existing organisation-wide Patient authority. Revoked/expired assignment and fresh permission revocation refuse contact. Foreign resources return 404 after permission checks.

The only domain write is `patient.whatsapp_opened` via `AuditRecorder`: Patient subject id, metadata `patient_id`, actor and branch. No phone, patient name, message or response is supplied. A missing audit record or exception blocks the redirect and rolls back. The event means opening the external chat destination was requested; it does not claim a message was sent or delivered. Throttle: **20 requests/minute per actor**, shared across contexts/branches. Successful redirects are private/no-store and no-referrer. Normal authentication/session/rate-limit infrastructure is unchanged.

## Number rules

`WhatsAppNumber::normalize` and `whatsAppNumber` share `tests/Fixtures/whatsapp-numbers.json` (44 vectors). Both accept ASCII digits, one optional leading `+` and common spaces (including Unicode Zs), parentheses, hyphens and single dots. They reject masks, letters, controls, multiple numbers, repeated dots, URLs, query text, empty/non-string and over-128-character values. Output is digits only.

Malaysian `0`, `60`, `+60` forms normalise to `60…`. The original 9–10-digit local mobile syntax is retained; the valid longer `011` form is also supported. Landline lengths are checked by area-prefix group (03, 04–07/09, 08). The original overlong non-011 cases remain refused. Foreign numbers still require leading `+`, a nonzero first digit and 8–15 digits. This is syntax eligibility, not proof of assignment or a WhatsApp account; existing Patient save validation remains stricter and unchanged.

All original invalid examples remain tested: the eight previously refused landline examples are now explicitly asserted as accepted in shared vectors, as required by the follow-up. No case was silently dropped.
